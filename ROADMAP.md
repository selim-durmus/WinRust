# WinRust: Roadmap

(Русская версия: [ROADMAP.ru.md](ROADMAP.ru.md))

Each item says how far it was checked: **tests** (unit tests), **built** (compiles, never run), **ran** (run by hand on a live system), **e2e** (full install/uninstall on a live system).

## Done

### Installer
- One `plugin-launcher.exe` with every plugin embedded (unpacked into Program Files, not %TEMP%), static CRT, dark Win32/GDI window. *ran*
- "Install WinRust" installs what is missing in order (topbar before rust-explorer), updates when everything is there; "Remove all" removes in reverse order. *built*
- A failed install undoes its own changes (not when updating a working copy); original values (WSearch, search box, Explorer settings, services) are saved under `HKLM\SOFTWARE\plugin-launcher\<plugin>` and put back on uninstall; non-fatal errors go to `%ProgramData%\plugin-launcher\install.log`. *built*
- Restore point before install. *built*
- Choose what to install (#7): a checkbox per component in the window, several names or `all` on the command line; a component that fails or is skipped does not stop the rest, the failures are listed at the end. A missing Windows Search service (stripped LTSC builds) is a warning, not an error, for both install and uninstall of rust-search. *built*
- The signed-in user, not the elevated account (#4): if UAC was answered with another administrator, per-user settings (HKCU, scheduled tasks, the PowerShell profile, the rust-search pipe permission, the rs-launcher Run key, debloat's HKCU policies) go to the owner of explorer.exe (or topbar / rust-explorer / rs-shell) in the session, through `HKU\<SID>`. If that user cannot be determined, install stops before writing anything. Uninstall carries on with a warning. *tests (key rewriting), built*
- One button installs what is missing **and** updates what is installed, so running a newer `WinRust.exe` brings its fixes to every plugin (v0.2.1). *built*
- Command line: `list | install <plugin>...|all --yes | update <plugin> | uninstall <plugin> | rollback --yes`, exit codes 0/1/2; the window and the command line call the same functions. Only the read-only commands were run. *ran (partly)*
- `update` and `scripts\update-plugin.ps1`: reinstall from `payload\` on disk without rebuilding the installer. *ran*
- English by default, Русский/English switch in the installer and in the bar menu; the choice is stored in `%ProgramData%\WinRust\lang.txt`. *tests*
- Review fixes (v0.3.0): rs-du keeps its quarantine list next to its exe (admin-only), `payload\` two levels up only from `target\release`, rtaskmgr and rust-explorer save and restore another program's Task Manager / folder settings, rust-search brings Windows Search back before removing its files, DiagTrack is left to debloat, one `reg query` parser with a test. *tests, built*
- Settings without Explorer (Win+I and the bar's menus): Settings is a Store app that opens only while Explorer is the shell, so a hidden helper starts Explorer, waits for its taskbar, opens the page, brings the window to the front (also over a fullscreen game), and puts rust-explorer back when Settings is closed; a hung Settings process is killed first. The bar hides only for fullscreen games and video. *built, ran by hand*
- Code layout: one cargo workspace; the installer split into `install/` (one file per plugin), `cli.rs`, `ui.rs`; shared `winrust-common` crate (language switch, MFT reader); one `payload.txt` list for the build and the scripts; CI on GitHub Actions. *tests*

### Plugins
- **rust-search**: NTFS search service + Alt+Space; disables WSearch, blocks SearchHost.exe, hides the taskbar search box. Right-click a result: rename, recycle bin, "delete permanently + clean the registry" (scan → confirm → delete; registry saved to `%LOCALAPPDATA%\rs-search\registry-backups\*.reg` first). *tests, ran*
- **rtaskmgr-win32**: replaces Task Manager through an IFEO Debugger (`taskmgr.exe` untouched); on a panic writes `%APPDATA%\rtaskmgr\crash.log` and opens the real Taskmgr. *tests, ran*
- **topbar**: Windows 11-style bottom bar instead of the taskbar; `topbar.exe --restore` brings the taskbar back. Installs with it: reshell hotkeys, rs-du, the PowerShell profile block (`src/install/profile.ps1`, Windows PowerShell 5.1 and pwsh 7). *ran; the profile block only on a temporary profile*
- **reshell safety net**: if topbar is not running while the taskbar is hidden, twice in a row (~10 s), it runs `topbar.exe --restore`. *tests; killing topbar was not tried*
- **reshell hotkeys**: Win+D (show desktop) and Win+I (Settings) work without Explorer, like Win+E (v0.2.1). *ran*
- **Styles** (v0.3.0): a gear at the left end of the bar switches Normal / Terminal / Floating dock / Tiling; the bar, rust-explorer and the search window repaint at once (a broadcast message, `%ProgramData%\WinRust\style.txt`). The dock reserves no screen space and slides away from maximized windows; Tiling puts the bar at the top and can tile the windows. *ran*
- **topbar look** (v0.3.0): the network icon is drawn (Wi-Fi arcs by signal, a cross when offline, "!" when there is no internet, per Windows' connectivity hint); new Wi-Fi panel (status, connected card with its own Disconnect button, saved/open networks, rows fade in); text-only menus with key hints; input language picker (left click on ENG/RUS); the tray flyout fades in and its chevron turns. *ran*
- **rust-explorer**: file manager (tabs, icons, IFileOperation copy/paste/delete, shell context menu, drag and drop), draws the desktop, turns off Explorer as the shell with `rs-shell --overlay` (90 s after sign-in at the latest: Windows 26300 no longer writes the autostart markers it used to wait for, v0.2.1), trims services. *tests, ran*
- **rust-explorer, fast and File Pilot-like**: folders are listed on a worker thread with `FindFirstFileExW` (large fetch) and refreshed when they change on disk (selection and scroll kept); a filter bar at the bottom filters as you type (typing in the list, Ctrl+F; arrows move, Enter opens, Esc clears, the other keyboard layout is understood); "Subfolders" (Ctrl+E) crawls the tree below with several threads into an in-memory index and searches it on every key (whole C:, 1.3 M entries: crawl 11 s with results as they come, about 30 ms per query); side pane with Recents, Bookmarks (Ctrl+D, the star), Storage and Places, foldable, with system icons; the last tabs come back at start; a settings page (gear, Ctrl+,) with switches saved in `%APPDATA%ust-explorer`. *tests, ran (filter, subfolders, settings page, tab restore checked on screen); the subfolder index does not follow later changes on disk (crawled again after a minute)*
- **rs-du**: disk cleaner (MFT analysis, caches, `target`/`node_modules`, recycle bin, 30-day quarantine), started from the bar menu. *tests*
- **wiztree**: disk-usage treemap from the MFT. *tests (layout only); not run on a live disk*
- **photoview**: WIC photo viewer, EXIF rotation, "Open with" entry. *ran; EXIF orientations 5 and 7 not checked*
- **debloat**: services and policies (telemetry, Copilot, Recall, ads, Edge background), old values in `%ProgramData%\winrust-debloat\undo.txt`, `--undo`. *dry run ran; `--apply`/`--undo` not run*
- **purge**: removes the bundled Store apps (installed and provisioned) and the telemetry scheduled tasks like Tiny11 does; OneDrive and Edge only with `--onedrive` / `--edge`. IRREVERSIBLE, a log in `%ProgramData%\winrust-purge
emoved.txt`. `purge.exe` lists, `--ask` asks for YES (the bar's right-click menu), `--apply` removes. Protected names (Store, Settings, Start, runtimes) are tested. *tests, dry run ran; `--apply` not run*
- **White road style and new topbar panels**: a fifth, light style (ivory, gold accent, low-poly triangles, some traced in gold, drawn with GDI+ behind the bar, its panels, rust-settings and Explorer's list in white); Quick settings and Wi-Fi panels redrawn: tiles with round icon badges and labels inside, sliders on one card with a shadowed knob, battery pill and round gear, an iOS-style switch, the connected network on its own card with a check mark (link speed and security on hover, Disconnect appears on hover), other networks on one card split by hairlines; a right click on a network opens a small menu (connect / disconnect, forget, known networks); while joining, the signal arcs sweep and a bar slides under the row until it connects or 25 s pass. rust-settings: values that used to step on each click (resolution, refresh rate, scale, orientation, display, screen mode, power plan, screen-off and sleep timeouts) open an animated drop-down list with the current value checked (arrows, Enter, Esc and the wheel work in it); a display without an EDID name reads "Built-in display" instead of `\\.\DISPLAY1`. `topbar --preview quick|wifi` shows a panel alone. *built, tests; panels screenshotted in White road and Tiling, rust-settings and Explorer in White road*
- **New look** (all programs): the shared palette is now neutral graphite with Apple's system blue (Normal), midnight ink with indigo (Floating dock), refined Terminal and Tiling; Apple's dark-mode green/yellow/red for status everywhere; Segoe UI Variable and Segoe Fluent Icons on Windows 11 (Segoe UI / MDL2 on Windows 10). rtaskmgr, the installer, wiztree and photoview moved from their own colours to the same graphite. rust-settings is redrawn like macOS System Settings: coloured page icons, grouped rounded cards with hairlines and section headers, iOS-style switches, smooth (GDI+) shapes, a centred content column, a floating bottom bar. `WINRUST_STYLE=<name>` previews a style in one process. *built, tests; rust-settings screenshots checked in all four styles, the other programs not looked at after the change*
- **rust-settings** (first steps): a small Settings window that needs neither Explorer nor the Store Settings app. Pages: Display (resolution and refresh rate of the primary display: a change is temporary, Enter keeps it, Esc or 15 s goes back; tested with `CDS_TEST` first), Sound (volume slider and mute of the default playback device, Core Audio), Power & storage (battery, power plan switch, free space on fixed drives), Network (Wi-Fi/Ethernet adapters and link speed; Wi-Fi: radio on/off, connect to saved, open and new networks with the password typed in the window (profile through the WLAN API, a failed attempt deletes it), hidden networks, disconnect/forget on right click, the result shown with Windows' reason text; scans about every 30 s, not on every refresh), Personalization (dark theme for apps/system, transparency, accent on title bars: four HKCU values), About (read-only), More (opens the system pages through the existing helper). Only documented Win32 calls, nothing run as a command. Installable like wiztree (a file in Program Files and a Start menu shortcut); once installed, Win+I and the bar menus open it for the exact addresses `ms-settings:` (display), `sound`, `personalization`/`colors`/`themes`, `powersleep`/`storagesense`, `network-status`, `about`, all others still go to Windows' Settings. Installer wiring only built, never run; Ethernet: only real cards (Hyper-V, VPN and Wi-Fi Direct adapters hidden), each with address, link speed and an internet dot from the Network List Manager; a click shows IPv4/IPv6, gateway, DNS, DHCP or manual, MAC. Next: Bluetooth, per-device volume. Wi-Fi password entry not tried on a live network yet. Written from scratch (the code offered in PR #14 was not used). Long pages scroll with the wheel, clickable rows highlight under the pointer. *tests (mode, slider, scroll and page-key logic), built, started; display change and volume not tried on a live system*
- **No more stubs in the settings** (rust-settings, the bar's quick settings, the task manager): rust-settings now has pages for Bluetooth (radio, airplane mode, paired devices with their connection state, pairing a nearby device, removal on a second click), Apps (installed programs, uninstall with a second click) and Windows Update (check, download and install through the Windows Update Agent; installing needs administrator rights). Sound: choose the playback and recording device (the default-device switch is the one undocumented call, the COM class every switcher uses) and the volume of each app. Display: night light (a colour filter of our own, a gamma ramp kept by a background `rust-settings --nightlight`, autostart through a HKCU Run value that uninstall removes; not Windows' schedule-driven one, which is an undocumented per-build blob) and the arrangement of several displays by dragging (snaps flush against a neighbour, Windows refuses gaps; a click picks the display). Network: VPN profiles (connect with the password Windows saved, disconnect), proxy (on/off, address, PAC script, applications told to re-read), Wi-Fi on every adapter and 802.1X (PEAP-MSCHAPv2: user name and password, the profile and per-user credentials through the WLAN API; EAP-TLS with certificates is not offered). Power & storage: disk cleanup (user temp files older than a day, recycle bin with Windows' own confirmation). The bar's quick-settings tiles Bluetooth, Airplane mode, Accessibility (Narrator, Magnifier, sticky and filter keys) and Energy saver show their state and act, with Russian labels; the Wi-Fi tile and panel use every adapter and send enterprise networks to rust-settings. Task manager: core affinity takes a 64-bit mask (winapi 0.3 declares it as 32-bit), so cores above the 32nd work (a process still lives in one processor group, up to 64 logical processors). *tests (new logic: addresses, colour gains, cleaning, snapping, picture mapping, EAP documents, mask), release builds, every page started for 9 s; not tried on a live system: pairing, VPN dialling, Windows Update install, the 802.1X sign-in (no such network at hand), the arrangement drag (one display here), and the quick-settings tiles*
- **Shortcuts closed**: reshell's watchdog restores the taskbar and then restarts the bar (up to 3 tries in a row, a bar stable for a minute gives them back); topbar remembers the user's own taskbar mode (auto-hide / always on top) in `%APPDATA%	opbar-taskbar-state.txt` and gives it back on exit and `--restore`; the rust-explorer desktop sizes its icon area from the real work area (bar at the top or bottom, any height, dock style) and follows changes; rust-settings gets a Scale step and an HDR switch for the primary display (orientation was already there). Night light stays a link to Windows. *built, tests; scale and HDR only read on a live system, not switched; the watchdog restart and the other changes not run on a live system*
- **Several displays and icons**: rust-settings picks the display its rows act on (resolution, rate, scale, orientation, HDR), switches extend / duplicate / one screen only (confirmed like a resolution, goes back after 15 s) and makes a display the main one. rust-explorer, rust-settings, topbar, wiztree, photoview and the installer got icons in one style (graphite tile, one coloured glyph, drawn 4x and shrunk: smooth at 16-256 px) from `scripts\make-icons.py`; rtaskmgr keeps its own. *built, tests; the display logic ran only on a one-display PC (reads), the icons were checked in the built exes*

- **v0.5.0, from the issue tracker**: the gear menu has "Hide the bar automatically" (`%ProgramData%\WinRust\autohide.txt`, off by default); Win+Shift+S is our own region clipper (a dimmed copy of the desktop, drag a rectangle, it goes to the clipboard and `Pictures\Screenshots`); the volume keys and Surface's power + volume-up work without Explorer; a keyboard button sits in the Start search; brightness goes through the video driver (`\\.\LCD`); the Wi-Fi switch goes through Windows' radio manager (the WLAN API cannot undo airplane mode); rust-explorer shows desktop shortcut names and mapped network drives, and Space opens a picture in photoview. *built, tests; brightness read and write ran on a laptop; the clipper, volume keys, Surface buttons, Wi-Fi and Bluetooth fixes not run on a live device*

## Next (in order)

(a) MTP/PTP phones have no drive letter, so they need the Windows Portable Devices API (`IPortableDeviceManager`, `IPortableDeviceContent`, enumerate objects, read and write through `IPortableDeviceResources` streams) behind a second "file system" in rust-explorer next to the path-based one; copy, paste, delete and drag and drop have to be redone on it. (b) Safe removal: a tray icon in topbar (it already hosts tray icons) that lists removable drives, and `CM_Request_Device_Eject` on the device node of the chosen drive (flush first, report "in use" with the process that holds it). (b) is the smaller half and works for USB sticks and disks; (a) is what the issue is mostly about. Needs a real phone and a USB stick to test: nothing here can be checked by unit tests alone.

## Known limitations
- System components are disabled or bypassed (reversibly), not removed: deleting `taskmgr.exe` or Windows Search outright would break system protection.
- Administrator rights are required.
- Win+S and Start still open Windows Search.
