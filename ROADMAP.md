# WinRust: Roadmap

(Русская версия: [ROADMAP.ru.md](ROADMAP.ru.md))

Each item says how far it was checked: **tests** (unit tests), **built** (compiles, never run), **ran** (run by hand on a live system), **e2e** (full install/uninstall on a live system).

## Done

### Installer
- One `plugin-launcher.exe` with every plugin embedded (unpacked into Program Files, not %TEMP%), static CRT, dark Win32/GDI window. *ran*
- "Install WinRust" installs what is missing in order (topbar before rust-explorer), updates when everything is there; "Remove all" removes in reverse order. *built*
- A failed install undoes its own changes (not when updating a working copy); original values (WSearch, search box, Explorer settings, services) are saved under `HKLM\SOFTWARE\plugin-launcher\<plugin>` and put back on uninstall; non-fatal errors go to `%ProgramData%\plugin-launcher\install.log`. *built*
- Restore point before install. *built*
- Choose what to install (#7): a checkbox per component in the window, several names or `all` on the command line; a component that fails or is skipped does not stop the rest, the failures are listed at the end. A missing Windows Search service (stripped LTSC builds) is a warning, not an error, for both install and uninstall of rust-search. *built*
- The signed-in user, not the elevated account (#4): if UAC was answered with another administrator, per-user settings (HKCU, scheduled tasks, the PowerShell profile, the rust-search pipe permission, the rs-launcher Run key, debloat's HKCU policies) go to the owner of explorer.exe (or topbar / rust-explorer / rs-shell) in the session, through `HKU\<SID>`. If that user cannot be determined, install stops before writing anything. Uninstall carries on with a warning. *tests (key rewriting), built*
- One button installs what is missing **and** updates what is installed, so running a newer `WinRust.exe` brings its fixes to every plugin (v0.2.1). *built*
- Command line: `list | install <plugin>...|all --yes | update <plugin> | uninstall <plugin> | rollback --yes`, exit codes 0/1/2; the window and the command line call the same functions. Only the read-only commands were run. *ran (partly)*
- `update` and `scripts\update-plugin.ps1`: reinstall from `payload\` on disk without rebuilding the installer. *ran*
- English by default, Русский/English switch in the installer and in the bar menu; the choice is stored in `%ProgramData%\WinRust\lang.txt`. *tests*
- Review fixes (v0.3.0): rs-du keeps its quarantine list next to its exe (admin-only), `payload\` two levels up only from `target\release`, rtaskmgr and rust-explorer save and restore another program's Task Manager / folder settings, rust-search brings Windows Search back before removing its files, DiagTrack is left to debloat, one `reg query` parser with a test. *tests, built*
- Settings without Explorer (Win+I and the bar's menus): Settings is a Store app that opens only while Explorer is the shell, so a hidden helper starts Explorer, waits for its taskbar, opens the page, brings the window to the front (also over a fullscreen game), and puts rust-explorer back when Settings is closed; a hung Settings process is killed first. The bar hides only for fullscreen games and video. *built, ran by hand*
- Code layout: one cargo workspace; the installer split into `install/` (one file per plugin), `cli.rs`, `ui.rs`; shared `winrust-common` crate (language switch, MFT reader); one `payload.txt` list for the build and the scripts; CI on GitHub Actions. *tests*

### Plugins
- **rust-search**: NTFS search service + Alt+Space; disables WSearch, blocks SearchHost.exe, hides the taskbar search box. Right-click a result: rename, recycle bin, "delete permanently + clean the registry" (scan → confirm → delete; registry saved to `%LOCALAPPDATA%\rs-search\registry-backups\*.reg` first). *tests, ran*
- **rtaskmgr-win32**: replaces Task Manager through an IFEO Debugger (`taskmgr.exe` untouched); on a panic writes `%APPDATA%\rtaskmgr\crash.log` and opens the real Taskmgr. *tests, ran*
- **topbar**: Windows 11-style bottom bar instead of the taskbar; `topbar.exe --restore` brings the taskbar back. Installs with it: reshell hotkeys, rs-du, the PowerShell profile block (`src/install/profile.ps1`, Windows PowerShell 5.1 and pwsh 7). *ran; the profile block only on a temporary profile*
- **reshell safety net**: if topbar is not running while the taskbar is hidden, twice in a row (~10 s), it runs `topbar.exe --restore`. *tests; killing topbar was not tried*
- **reshell hotkeys**: Win+D (show desktop) and Win+I (Settings) work without Explorer, like Win+E (v0.2.1). *ran*
- **Styles** (v0.3.0): a gear at the left end of the bar switches Normal / Terminal / Floating dock / Tiling; the bar, rust-explorer and the search window repaint at once (a broadcast message, `%ProgramData%\WinRust\style.txt`). The dock reserves no screen space and slides away from maximized windows; Tiling puts the bar at the top and can tile the windows. *ran*
- **topbar look** (v0.3.0): the network icon is drawn (Wi-Fi arcs by signal, a cross when offline, "!" when there is no internet, per Windows' connectivity hint); new Wi-Fi panel (status, connected card with its own Disconnect button, saved/open networks, rows fade in); text-only menus with key hints; input language picker (left click on ENG/RUS); the tray flyout fades in and its chevron turns. *ran*
- **rust-explorer**: file manager (tabs, icons, IFileOperation copy/paste/delete, shell context menu, drag and drop), draws the desktop, turns off Explorer as the shell with `rs-shell --overlay` (90 s after sign-in at the latest: Windows 26300 no longer writes the autostart markers it used to wait for, v0.2.1), trims services. *tests, ran*
- **rust-explorer, fast and File Pilot-like**: folders are listed on a worker thread with `FindFirstFileExW` (large fetch) and refreshed when they change on disk (selection and scroll kept); a filter bar at the bottom filters as you type (typing in the list, Ctrl+F; arrows move, Enter opens, Esc clears, the other keyboard layout is understood); "Subfolders" (Ctrl+E) crawls the tree below with several threads into an in-memory index and searches it on every key (whole C:, 1.3 M entries: crawl 11 s with results as they come, about 30 ms per query); side pane with Recents, Bookmarks (Ctrl+D, the star), Storage and Places, foldable, with system icons; the last tabs come back at start; a settings page (gear, Ctrl+,) with switches saved in `%APPDATA%\rust-explorer`. *tests, ran (filter, subfolders, settings page, tab restore checked on screen); the subfolder index does not follow later changes on disk (crawled again after a minute)*
- **rust-explorer, zoom and folder totals**: Ctrl+wheel (or Ctrl+Plus / Minus, Ctrl+0) walks the views like File Pilot: Details (compact rows that keep their size), Tree (folders open in place with an arrow, Right / Left keys), List, then pictures growing in small steps from medium through large to extra large icons, gliding between sizes; every other row is shaded; an empty result shows on a clean page; nothing is reloaded: pictures (thumbs.rs) are asked from the shell once at 64 / 128 / 256 px, kept as GDI+ bitmaps on their own pixels and drawn scaled, both views are drawn by hand; the mouse's side buttons and the keyboard's Back / Forward keys go back and forward; the wheel glides in the list and the side pane; Folders / Files / Size columns count what is inside each folder in the background (sizes.rs, four threads, kept two minutes, not on network drives; a setting); the address box lets go when you click elsewhere; the columns always fill the width. *tests, ran (zoom, row heights, folder totals, address box checked on screen); the list itself still scrolls by rows (the Windows list control): pixel-smooth scrolling needs a list of our own, the next step*
- **rust-explorer, a quieter window**: no system title bar: the tabs (each with its folder's icon, hairlines between them), "+" and the minimize / maximize / close buttons share the top row, whose empty part drags the window; the filter floats over the list's bottom-left corner with only the Subfolders glyph beside it; the bottom-right corner shows the counts, the view and the zoom in percent, and a slider (Details, Tree, List, M / L / XL Icons) appears while zooming or on a click; the view button, the bottom bar and other labels are gone; smaller names; at most five recent places. Fixed: rows jumping up and down while scrolling (forcing the horizontal scrollbar away fought the list control; the columns now leave a few pixels instead). *tests, ran (title bar, tabs, floating bars, slider, scrollbars checked on screen)*
- **rust-explorer, its own right-click menu** (menu.rs): the shell's items for the selected files (every program's own entries, Send to, Open with) read out of the menu the shell fills in and shown in a small dark window with a search box on top that also finds items inside submenus; Give access to, Restore previous versions, Include in library and Copy as path are left out; key hints on the right; submenus open on hover or Right; the folder and side-pane menus use the same window. Also: the wheel's glide no longer swings one row up and down forever at exactly half a row left; a smaller close cross on the tabs. *tests, ran (menu, icons, search and closing checked on screen); items a shell extension draws itself without text (NordVPN Meshnet) are not shown yet*
- **rust-explorer, drag and drop and smaller fixes**: dragging over a folder lights it up and dropping moves the files into it (copies across drives or with Ctrl; dropping where they already are does nothing); the menu stays inside the window and opens upward when there is no room below; a click outside an open menu closes it and still does its job (a right click on another file opens that file's menu); "Pin to Start" / "Pin to taskbar" in the menu go to the bar (`topbar --pin-bar` and a WM_COPYDATA request are new), Windows' own pins and Quick access are left out, folders get Bookmark; two empty rows after the last one leave room to right-click the folder itself; going up or back selects the folder you came out of; the floating bars are thinner; no more blank "This folder is empty" frame (the rows are swapped with drawing off, and no reload after a menu or a drag: the folder watcher brings real changes). *tests, ran (menu, came-from selection, empty rows checked on screen); dragging onto a folder not tried by hand; Pin to taskbar needs topbar updated*
- **rust-explorer, tree side pane and menu clean-up**: the side pane is a tree (the user folder holds Desktop, Downloads ...; drives and bookmarks open the same way; a chevron opens a folder in place, which ones are open is remembered); Delete on a menu item hides it in every menu from now on (Settings > "Show hidden menu items" brings them back), and Take ownership, Send to and Add to Favorites are gone; a new folder or file comes up selected with its name open for typing (a file's name without the extension), the rename box sits over the name in the list's colours; holding a drag over another tab opens it, and dropping on a tab moves into its folder; the zoom slider opened from the corner stays until a click anywhere else; Settings buttons react only on themselves. *tests, ran (tree, menu hiding, new-folder rename, slider, settings checked on screen); a drag held over a tab not tried by hand*
- **rust-explorer, slimmer top and a shorter side pane**: Places holds only Desktop, Downloads, Documents, Pictures and the Recycle Bin (opened by the shell); the search button left the toolbar (the filter is at the bottom, Ctrl+F); the tab row and toolbar are thinner with smaller icons; the menu's key hints are smaller; in the menu's search Ctrl+Backspace / Ctrl+Delete delete a word and Ctrl+A selects all (no more box characters). *tests, ran (checked on screen)*
- **rust-explorer, side pane beside the tabs**: the side pane runs the full height, its top is part of the title row with a button that hides it; the tabs and toolbar start right of the pane, and with the pane hidden its button leads the tab row (remembered as `side_pane`). *tests, ran (both states checked on screen)*
- **rust-explorer, selection box, Ctrl+Z and the usual keys**: dragging from anywhere but a name (beside it, another column, under the rows) draws a selection box, scrolling at the edges (Ctrl / Shift add to the selection), while dragging a name still moves the file; Ctrl+Z takes back the last delete (restored from the Recycle Bin), move, copy, rename or new item, also from the folder menu's top line while there is something to undo; Ctrl+A, Esc, Shift+Delete (for good, the shell asks), Ctrl+Shift+C (paths as text), Ctrl+R, Ctrl+1..9 and Ctrl+Shift+Tab for tabs; the menu's Delete goes through the same undoable path. *tests, ran (box, Ctrl+A, undo of delete / rename / new folder / copy checked on screen); undo of a move not tried by hand; no redo yet*

## Next (in order)
0. **Phones and safe removal in rust-explorer** (#2): not started, too big for a quick fix. (a) MTP/PTP phones have no drive letter, so they need the Windows Portable Devices API (`IPortableDeviceManager`, `IPortableDeviceContent`, enumerate objects, read and write through `IPortableDeviceResources` streams) behind a second "file system" in rust-explorer next to the path-based one; copy, paste, delete and drag and drop have to be redone on it. (b) Safe removal: a tray icon in topbar (it already hosts tray icons) that lists removable drives, and `CM_Request_Device_Eject` on the device node of the chosen drive (flush first, report "in use" with the process that holds it). (b) is the smaller half and works for USB sticks and disks; (a) is what the issue is mostly about. Needs a real phone and a USB stick to test: nothing here can be checked by unit tests alone.
0. **Taskbar-style reordering in topbar** (#6, wish): dragging a file onto the bar already pins it. Missing: dragging the window buttons to change their order, and dragging a button off the bar to unpin. Needs the order stored (like `topbar-start.txt`) and a drag state in `topbar` (mouse capture, an insertion marker, a repaint per move).

## Known limitations
- System components are disabled or bypassed (reversibly), not removed: deleting `taskmgr.exe` or Windows Search outright would break system protection.
- Administrator rights are required.
- Win+S and Start still open Windows Search.
